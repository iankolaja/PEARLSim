# Run archive policy

v1 kept every file of every step: about 340 MB per step and ~4.6 TB in all. v2 archives
only what the ML tables, restarts and branching from checkpoints need.
`scripts/pack_run.py RUN_DIR` reports what the policy keeps. Without `--tar` it changes
nothing. With `--tar OUT.tar.gz` it writes the kept files to a compressed tar, and the run
directory is left as it is.

| Kept | Why |
|---|---|
| `<sim>_record_<i>.json` | the per-step record (`pearlsim/records.py`); the ML table is gathered from these |
| `<sim>_operating_<i>.json`, `zone_map<i>.json`, discharge / discard / held inventories, replica spread | inputs to records; zone maps are also needed by `load_from_step` |
| `<deck>_res.m`, `<deck>_det<k>.m`, `<deck>.wrn` | Serpent results and warnings; records can be rebuilt from them |
| final `<deck>.bumat<N>` of each replica | restart replay (`serpent_flag 2`) and `load_from_step` read them |
| `pebble_positions_<i>*.csv`, `core_materials_<i>.json.gz` at checkpoint steps (every 10th and the last) | branching from checkpoints |

| Dropped | Why it is safe |
|---|---|
| decks (`.serpent`) | regenerated deterministically from the deck file, `set_seed` and the kept `.bumat` files |
| `_dep.m` (~216 MB per step), `.out`, the binary depletion file `.dep` (used only by `sss2 -rdep` to rebuild `_dep.m`; not a restart file), `.seed`, `.log`, geometry plots, `bumat0` | not used by PEARLSim; the depletion history is summarised in the kept compositions |
| pebble positions and core materials between checkpoints | regenerated by replaying the deck |

Files that match no rule are kept and reported as `unknown`, so a new output type is never
dropped silently.

Example (v1 `gFHR_benchmark_1975`, 240 Serpent steps): kept 5.2 GB, dropped 80.4 GB, before
compression.
